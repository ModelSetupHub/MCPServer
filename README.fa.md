# ModelSetupHub — MCPServer

**سروری بر پایه‌ی MCP که کل جعبه‌ابزار ModelSetupHub را در اختیار یک AI agent می‌گذارد.**

[English](README.md) · فارسی

MCPServer به یک دستیار هوش مصنوعی اجازه می‌دهد مدل‌های AI محلی را برای شما راه‌اندازی کند. به‌جای اینکه خودتان مدل را
انتخاب کنید، حساب کنید که در GPU شما جا می‌شود یا نه، و دنبال پارامترهایی بگردید که سریعش می‌کنند، هدف را توصیف
می‌کنید — *یک مدل کدنویسی مناسب سیستم من نصب کن* — و agent با همین ابزارها سخت‌افزارتان را بررسی می‌کند، Ollama را
مدیریت می‌کند، مدل‌ها را دانلود و کانفیگ می‌کند، و تنظیمات را در برابر هم بنچمارک می‌کند.

این سرور با پروتکل Model Context Protocol حرف می‌زند، پس به هر کلاینت سازگار با MCP — از جمله Claude Desktop — وصل
می‌شود.

## جای این ریپو در پروژه

ModelSetupHub سه ریپو روی یک موتور مشترک است.

| ریپو | چیست | کِی به آن سر بزنید |
| --- | --- | --- |
| [Core](https://github.com/ModelSetupHub/Core) | کتابخانه‌ی پایتونی که کار را انجام می‌دهد | وقتی خودتان اسکریپت یا automation می‌نویسید |
| [WebApp](https://github.com/ModelSetupHub/WebApp) | داشبورد وب محلی روی همان توابع | وقتی رابط گرافیکی و کنترل کامل دستی می‌خواهید |
| **MCPServer** (همین) | سرور MCP که همان ابزارها را به یک AI agent می‌دهد | وقتی ترجیح می‌دهید هدف را به زبان معمولی توصیف کنید |

این مسیر دوستانه‌تر است: agent ترتیب کارها را تعیین می‌کند و توضیح می‌دهد که دارد چه می‌کند. داشبورد نقطه‌ی مقابل آن
است، برای کسانی که از قبل می‌دانند دقیقاً چه مدل و چه پارامترهایی می‌خواهند. هر دو با کتابخانه‌ی یکسانی کار می‌کنند، پس
روی یک دستگاه قابل جایگزینی با یکدیگرند.

## agent چه کارهایی می‌تواند بکند

در مجموع ۵۶ ابزار. همه‌ی آن‌ها واسطه‌ی مستقیم به جعبه‌ابزار هستند، پس agent همان توانایی‌هایی را در اختیار دارد
که یک اسکریپت دارد. دسته‌بندی‌شان به‌این‌ترتیب است:

- **سیستم** — اسکن کامل دستگاه، یا خواندن فقط جزئیات حافظه، فضای ذخیره‌سازی، GPU یا CUDA.
- **سرویس Ollama** — بررسی نصب و در حال اجرا بودن Ollama، روشن و خاموش کردنش، نصب خودِ Ollama، و خواندن فایل‌های لاگ خودِ
  Ollama برای وقتی چیزی شکست خورده و دلیلش همان‌جا دفن شده است.
- **مدل‌ها** — فهرست مدل‌های نصب‌شده و بارگذاری‌شده، مشاهده‌ی جزئیات یک مدل، اجرای پرامپت، پیش‌بارگذاری و تخلیه از حافظه،
  ثبت یک فایل GGUF محلی، ساختن کپی کانفیگ‌شده از یک مدل، و حذف مدل.
- **بنچمارک** — اجرای مجموعه‌ای از پرامپت‌ها با یک کانفیگ، یا مقایسه‌ی چند کانفیگ یا چند مدل روی همان پرامپت‌ها؛ همراه با
  زمان رسیدن به اولین توکن و خواندن‌های VRAM و GPU برای هر پرامپت، میانگین‌گیری از تکرارها به‌همراه آمار نوسان، حکم معناداری
  برای هر مقایسه، و تاریخچه‌ای از اجراهای گذشته برای مرور، خواندن دوباره یا حذف.
- **پایتون** — ساختن و حذف محیط مجازی، نصب و حذف و فهرست کردن پکیج‌ها، نوشتن و خواندن و ویرایش و حذف و اجرای اسکریپت، و
  نصب خودِ پایتون از نصب‌کننده‌ی رسمی.
- **دانلود** — گرفتن یک فایل در یک فراخوانی، یا ساختن صف، شروع آن، دنبال کردن پیشرفتش، نگه داشتن موقت، ادامه دادن، گذشتن
  از یک فایل یا لغو کل صف. دانلود
  فقط از فهرست ثابتی از میزبان‌های مورد اعتماد مجاز است و ابزاری هست که گزارش می‌دهد آن‌ها کدام‌اند.
- **لاگ‌ها** — خواندن لاگ اجرای جعبه‌ابزار با فیلتر، یا فقط بررسی حجمش پیش از خواندن.

هر ابزار حاشیه‌نویسی‌هایی همراه خود دارد تا کلاینت بتواند فراخوانی فقط-خواندنی را از فراخوانی‌ای که چیزی روی دستگاه شما
تغییر می‌دهد تشخیص دهد. نوشتن در لاگ اجرا عمداً ارائه نشده است — جعبه‌ابزار ورودی‌های خودش را می‌نویسد، و اجازه دادن به
کلاینت برای تزریق رکورد، تاریخ اجرا را خراب می‌کرد.

## پنل پیشرفت

دانلود، بنچمارک و ایمپورت مدل چند دقیقه طول می‌کشند، و این برای سکوت یک گفتگو زیادی طولانی است. این عملیات‌ها نسخه‌ای دارند که
**یک نمای پیشرفت زنده داخل خودِ گفتگو** رسم می‌کند، کنار پیام دستیار: برای دانلود و بنچمارک درصد کلی و یک سطر برای هر فایل یا
هر کانفیگ، و برای ایمپورت مدل فقط نام مدل و یک بج وضعیت — در طول اجرا هیچ
چیز دیگری نیست و فقط اگر به خطا بخورد متنی زیر عنوان می‌آید. ایمپورت عمداً نه
درصدی نشان می‌دهد نه دکمه‌ی Cancel دارد: خوندنی که
اول ایمپورت می‌آید طولانی و غیرقابل اندازه‌گیری است، یک نوار اول صفر می‌ماند و بعد در حالی که کار هنوز ادامه دارد تا ۱۰۰
می‌پرد، و ایمپورت به حال خودش رها می‌شود تا تمام شود.

پنل کنترل‌های خودش را دارد و کارشان با هم متفاوت است:

- **Cancel** عملیات را تمام می‌کند *و آن را برمی‌گرداند*. دانلود لغو‌شده فایل‌هایی را که تولید کرده حذف می‌کند؛ بنچمارک
  لغو‌شده اندازه‌گیری‌های نیمه‌کاره‌اش را دور می‌ریزد و مدلی را که بارگذاری کرده بود از حافظه خارج می‌کند. این کار قابل بازگشت
  نیست، و روی نمای ایمپورت مدل اصلاً ظاهر نمی‌شود.
- **Stop** فقط برای دانلودها ظاهر می‌شود و تنها انتقال را معلق می‌کند. صف و داده‌ی دریافت‌شده حفظ می‌شوند و فشار دادن
  دوباره‌اش فایل جاری را از همان‌جا که مانده ادامه می‌دهد.

نوار پیشرفت بعد از رفرش صفحه یا باز کردن دوباره‌ی گفتگو هم کار می‌کند، چون وضعیتش روی دیسک ذخیره می‌شود نه در حافظه.
عملیات‌هایی که چیز قابل اندازه‌گیری برای گزارش ندارند — نصب‌ها، اسکن سخت‌افزار — نسخه‌ی پیشرفت‌دار ندارند.

## پیش‌نیازها

- پایتون ۳.۱۰ یا جدیدتر
- ویندوز برای مجموعه‌ی کامل قابلیت‌ها. شناسایی سخت‌افزار بر PowerShell و WMI و شناسایی GPU بر `nvidia-smi` تکیه دارد.
- Git، برای دریافت ساب‌ماژول `Core`
- یک کلاینت سازگار با MCP

وابستگی‌ها در `requirements.txt` فهرست شده‌اند. خودِ جعبه‌ابزار از ساب‌ماژول `Core` می‌آید و وابستگی‌های خودش را همراه
دارد.

## راه‌اندازی

جعبه‌ابزار در ساب‌ماژول `Core` قرار دارد و اول باید به‌صورت پکیج نصب شود. یک ابزار کمکی همراه پروژه این کار را برایتان
انجام می‌دهد:

<div dir="ltr">

```bash
git clone --recurse-submodules https://github.com/ModelSetupHub/MCPServer.git
cd MCPServer

# already cloned without --recurse-submodules? fetch it now:
git submodule update --init

python utils/install_mshcore.py
```

</div>

یا مستقیماً با `pip install ./Core` نصبش کنید. بعد وابستگی‌های خودِ سرور:

<div dir="ltr">

```bash
pip install -r requirements.txt
```

</div>

این ابزار کمکی سه سوییچ هم می‌پذیرد: `--check` گزارش می‌دهد که جعبه‌ابزار از قبل نصب هست یا نه، `--editable` نصب توسعه
انجام می‌دهد، و `--force` نصب دوباره می‌کند — که بعد از گرفتن یک کامیت جدیدتر از ساب‌ماژول به کار می‌آید.

## اجرا

<div dir="ltr">

```bash
python main.py
```

</div>

سرور روی ورودی و خروجی استاندارد ارتباط برقرار می‌کند، پس کلاینت خودش آن را اجرا می‌کند. در کانفیگ کلاینتتان ثبتش کنید:

<div dir="ltr">

```json
{
  "mcpServers": {
    "modelsetuphub": {
      "command": "python",
      "args": ["C:/path/to/MCPServer/main.py"]
    }
  }
}
```

</div>

اگر کلاینت شما Claude Desktop است، `utils/claude_setup.py` همین ثبت را برایتان انجام می‌دهد. این یک برنامه‌ی دسکتاپ
کوچک و مستقل است — نه یک ابزار MCP — که می‌تواند Claude Desktop را نصب کند، مفسر پایتون و فایل کانفیگ شما را خودکار پیدا
کند، و سرورهای MCP را اضافه یا حذف کند، و پیش از هر تغییر از کانفیگ نسخه‌ی پشتیبان می‌گیرد. برای شناسایی و نصب به ویندوز
نیاز دارد:

<div dir="ltr">

```bash
python utils/claude_setup.py
```

</div>

## خوب است بدانید

- **این ابزارها دستگاه شما را تغییر می‌دهند.** نرم‌افزار نصب می‌کنند، نصب‌کننده اجرا می‌کنند، مدل حذف می‌کنند و پوشه
  پاک می‌کنند. مرور کردن آنچه agent پیشنهاد می‌دهد پیش از تأیید کردنش، ارزش لحظه‌ای را که می‌گیرد دارد.
- **حذف مدل قابل بازگشت نیست**، و لغو کردن یک دانلود فایل‌هایی را که آن دانلود تولید کرده حذف می‌کند.
- **یک نشست دانلود لغو‌شده دیگر قابل شروع دوباره نیست.** دانلود دوباره‌ی همان فایل‌ها یعنی شروع یک نشست تازه، و همین است
  که جلوی دو بار اجرا شدن یک صف را می‌گیرد.
- **خطاها عیناً منتقل می‌شوند.** وقتی جعبه‌ابزار چیزی را رد می‌کند، دلیل واقعی به کلاینت می‌رسد نه یک خطای عمومی — مثلاً
  دامنه‌ی دانلود مسدود، با نام خودش گزارش می‌شود.
